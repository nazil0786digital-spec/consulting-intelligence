# v0.2.0 — Phase 2 Knowledge and Evidence Workspace

## What users can do

- Create an organization-scoped workspace and upload approved UTF-8 text, text-based PDF, or DOCX knowledge.
- Classify uploaded knowledge as a guide, requirement, release note, SOP, incident, historical case, RCA, or general document.
- Submit an issue and receive an evidence pack built from only that workspace's indexed knowledge.
- Review citations with page or paragraph locations, source type, SHA-256 file integrity reference, extracted issue context, missing information, and a recommended next step.

## Technical highlights

- Tenant-scoped persistence, ingestion, chunking, duplicate detection, and knowledge retrieval.
- Text-based PDF and DOCX extraction performed locally; original-upload hashes are retained.
- Hybrid lexical and vector retrieval with a bounded, documented source-authority adjustment.
- PostgreSQL pgvector storage contract with an offline SQLite development fallback.
- Deterministic issue-context extraction for explicit client, module, version, and issue-type clues.

## Verification

- Automated: 15 API tests cover evidence packs, tenant isolation, ingestion, PDF and DOCX locators, source-type validation, retrieval, issue extraction, and the pgvector column contract.
- Manual: Next.js production build passed.

## Known limitations

- Only text-based PDFs are supported; scanned PDFs require OCR and are rejected when they contain no extractable text.
- No sign-in, role management, production migrations, or cloud file storage yet.
- Embedding uses a deterministic local fallback by default; OpenAI embeddings require private environment configuration.
- Jira and client-response drafts remain review-only; no external action occurs.
