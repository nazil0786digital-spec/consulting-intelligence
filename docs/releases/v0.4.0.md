# v0.4.0 — Phase 4 Approval Driven Integration Foundation

## What users can do

- Prepare a Jira handoff payload from a workspace investigation.
- Review and approve that handoff internally, with a recorded approval timestamp.
- Inspect the n8n-compatible approved-handoff event that a future workflow could consume.

## Technical highlights

- Tenant-scoped Jira handoff preview containing the issue summary, labels, review notice, and evidence IDs.
- Approval state is separate from external delivery and is recorded against the investigation.
- n8n-compatible event is unavailable before approval and always returns `delivery: disabled`.
- Cross-workspace access and approval attempts are rejected.

## Verification

- Automated: 16 API tests cover tenant isolation, knowledge ingestion, quality checks, pilot feedback, approval gates, and n8n event preview behavior.
- Manual: Next.js production build passed.

## Known limitations

- No Jira, n8n, email, or other external system is connected or contacted.
- Internal approvals have timestamps but no reviewer identity because authentication is not implemented.
- No webhook URL or credentials are stored in the application.

## Next

Before enabling a real external delivery, select the target system and account, add authentication and reviewer identity, define the approval policy, and conduct a controlled integration test.
